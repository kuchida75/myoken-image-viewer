# Local Viewer Dependencies

The viewer loads these bundled files locally. Keep the DLLs, Codecs, Models and Licenses directories alongside the executable. No models or codecs are downloaded at application runtime. ONNX Runtime telemetry is disabled by the viewer.

## Image Codecs

Magick.NET-Q8-x64 and Magick.NET.Core 14.16.0 provide WebP, AVIF, JPEG XL, HEIC/HEIF and GIF reading. The 8-bit native Windows library includes libheif/libde265, libwebp and libjxl. HEIC writing is not enabled. Magick.NET is Apache-2.0; its native components have their own licenses. The complete upstream `Notice.txt` is included as `Licenses/Magick.NET-notices.txt`.

`Codecs` contains the upstream configuration resources plus the viewer's raster-only `policy.xml`. External delegates/filters and unlisted formats are disabled. Native pixel-cache memory is capped at 512 MB per process, with up to 2 GB temporary disk cache. Completed WPF display bitmaps and GIF playback frames are separate from this native working memory. These are not VRAM limits.

Packages and SHA256 hashes are pinned in `tools/codec-dependencies.json`. `tools/prepare-codec-dependencies.ps1 -Download` restores the original managed/native DLLs and configuration resources while retaining the viewer policy. Source and upstream releases: https://github.com/dlemstra/Magick.NET/releases/tag/14.16.0 .

## Models

- [Real-ESRGAN](https://github.com/xinntao/Real-ESRGAN), `realesrgan-x4plus-128.onnx`, exported from the official RealESRGAN_x4plus.pth release with PyTorch 2.6.0 CPU, spandrel 0.4.1 and ONNX 1.17.0. BSD-3-Clause license retained in Licenses/Real-ESRGAN.txt. Fixed [1,3,128,128] RGB float input in [0,1], 4x RGB output; ONNX opset 17. Model/checkpoint hashes and download provenance are pinned in tools/upscale-models.json and verified before inference.
- [Real-HAT](https://github.com/XPixelGroup/HAT), `real-hat-gan-x4-128.onnx`, exported from Real_HAT_GAN_SRx4.pth, the fidelity-oriented real-world variant (not sharper). The checkpoint was retrieved from the hfmaster/models-moved mirror and pinned by its LFS SHA-256; original distribution is linked by XPixelGroup via Google Drive/Baidu. Apache-2.0 license retained in Licenses/HAT.txt. Same fixed RGB input/output contract and export toolchain as Real-ESRGAN. See tools/export-upscale-models.py for reproducible export; Python is not a viewer runtime dependency for these ONNX models.
- [SwinIR-M Real-World x4](https://github.com/JingyunLiang/SwinIR), `swinir-m-realworld-x4-128.onnx` (57,808,208 bytes), exported from the official v0.0 release `003_realSR_BSRGAN_DFO_s64w8_SwinIR-M_x4_GAN.pth`, specifically its `params_ema` weights. Medium real-world GAN model, not the large, lightweight or classical variant. Uses the same FP32 RGB tile contract and toolchain as above; 128px tiles and 32px halos align to its 8px attention windows. Checkpoint/model SHA-256 and provenance are pinned in tools/upscale-models.json; upstream Apache-2.0 license is retained in Licenses/SwinIR.txt. Re-export only this model with `tools/export-upscale-models.py --model swinir` from the pinned export environment. The viewer preserves source chroma/alpha and bounds luminance reconstruction through its existing regional blend, rather than displaying unmodified upstream RGB output.
- SUPIR is NOT bundled. Tools/viewer-supir.py is an optional adapter to the user's separately installed, trusted SUPIR/CUDA/Python environment and locally configured SDXL/SUPIR-v0F/text-encoder weights. Its inference has not been validated in this build; only setup/routing/guards are tested. It runs offline without LLaVA; users must review upstream code and checkpoint licenses before installing. Executable/repository paths are machine-local and excluded from session backups.

- [ONNX Model Zoo sub-pixel CNN super-resolution](https://github.com/onnx/models/tree/main/validated/vision/super_resolution/sub_pixel_cnn_2016), `super-resolution-10.onnx` (240,078 bytes), opset 10, Apache-2.0 repository license retained in `Licenses/ONNX-super-resolution.txt`. This is the pretrained BSD300 luminance reconstruction model, not a generative face-restoration model. The viewer uses 224x224 reflected-edge tiles with 16 input pixels of halo, native 3x inference, area filtering to the requested scale and chroma-preserving regional blending. The model and its SHA-256 are pinned in the dependency manifest and verified before inference. Subject and human masks come from the two models below; mask and skin-color estimates can be wrong.
- PPHumanSeg, human_segmentation_pphumanseg_2023mar.onnx from [OpenCV Zoo](https://github.com/opencv/opencv_zoo/tree/main/models/human_segmentation_pphumanseg), stored here as Models/humanseg.onnx. OpenCV specifies Apache 2.0 for all files in that model directory. License is in Licenses/PPHumanSeg.txt. RGB input is resized to 192x192 and normalized by mean/std 0.5; output channel 1 supplies person probabilities. Copyright (C) 2021, Shenzhen Institute of Artificial Intelligence and Robotics for Society; third-party copyrights remain with their owners.
- [U-2-NetP](https://github.com/xuebinqin/U-2-Net), Qin et al., Pattern Recognition 2020, using the u2netp.onnx conversion distributed in the [rembg model release](https://github.com/danielgatis/rembg/releases/tag/v0.0.0). The upstream U-2-Net repository's Apache 2.0 license is included as Licenses/U-2-Net.txt. The rembg release has no separate model-specific license/provenance file; review the originating checkpoint and training-data terms before commercial redistribution. RGB input is resized to 320x320, divided by the visible sample's maximum channel, then ImageNet-normalized. The first output supplies foreground probabilities. This implementation uses raw confidence instead of stretching an uncertain mask to black/white. rembg Python code is not bundled.

These are approximate segmentation models, not face recognition or calibrated skin segmentation. They can miss hair, transparent objects, small people or unusual scenes. No identity, ethnicity or complexion classification is performed.

## Integrity And Rebuilding

The SHA-256-pinned package/model manifest is tools/enhancement-dependencies.json. Model hashes are also checked before loading by SubjectSegmentation. Normal builds use the bundled files and need no package restore/network connection. To recreate runtime binaries/models from the pinned downloads, run tools/prepare-enhancement-dependencies.ps1 -Download from the source project root. The model license files are already supplied here and should be retained.

DirectML uses the adapter chosen under Configure > Performance (Auto prefers discrete GPUs), sequential execution and disabled memory patterns as required by [ONNX Runtime DirectML](https://onnxruntime.ai/docs/execution-providers/DirectML-ExecutionProvider.html). Session creation or inference failure retries with CPU; CPU inference uses up to eight threads with idle spinning disabled. Subject inference and upscale jobs each have a process-wide gate. Subject sessions are reused while Advanced remains enabled, then asynchronously disposed on Off, Basic mode, or window close. Upscale sessions are scoped to the cancelable preview job; color/detail blending runs in parallel on CPU.

Model inference memory is separate from the decoded-image budget. DXGI pressure and the AI soft limit are checked before admitting sessions and between upscale tiles. These are soft admission checks, not hard driver-allocation limits. There is no unified VRAM pool. Rendering is the existing WPF PS 2.0 pipeline, not a new D3D12 image decoder.
