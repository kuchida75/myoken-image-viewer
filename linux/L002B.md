# L002b - image zoom, pan and actual-size viewing

Status: candidate source. Compilation and geometry checks passed on the first CI attempt; that attempt exposed an incorrect root-coordinate assumption in the synthetic wheel test. The test mapping has been corrected, input assertions retained, and drag/capture checks added. Use the completed run for the final source revision before advancing linux/ubuntu-gnome. Native GNOME acceptance of this iteration is pending.

## User controls

Image tabs have Fit, 100%, minus/plus controls and a zoom indicator. Wheel zoom is anchored at the pointer, subject to centring/pan bounds at image edges. Left- or middle-button dragging pans an enlarged image; capture is released on pointer-up, capture loss or tab detachment. Double-click toggles Fit/100%. With the image viewer focused, 0 means Fit, 1 means 100%, +/- zoom, and arrow keys pan. Existing Ctrl+L, Ctrl+W and F11 remain window shortcuts. The folder browser's arrow keys still navigate thumbnails.

Fit shows the whole image without upscaling a small source. 100% maps one source pixel to one **application render-target pixel**, accounting for Avalonia RenderScaling, and aligns the image origin to that pixel grid. The XWayland/compositor output can be scaled again by the desktop; this is not a claim of physical monitor-pixel parity under every GNOME fractional-scaling configuration.

Each open tab retains zoom/pan in memory while switching tabs. The inactive tab releases decoded image pixels; switching back reloads as required without resetting its geometry. Existing folder/tab/active-tab persistence is unchanged. Zoom/pan itself is **not persisted across application restart** in this iteration. Reopened tabs start in Fit.

## Decode and resource limits

The viewer initially requests a 4096-pixel-long-edge preview, retaining original header dimensions. When zoom needs more detail than that preview contains, it reads the source at full resolution in the background; the display explicitly says preview while pending or if the full decode fails. It does not label an enlarged reduced bitmap as full resolution. The viewport transform does not change when higher-resolution pixels arrive.

Full-resolution viewing is guarded at 64,000,000 source pixels (about 244 MiB for one RGBA8 output buffer). Larger accepted inputs retain preview viewing, show a warning, disable 100%, and restrict manual zoom to available preview detail. The existing 120,000,000-pixel input ceiling remains. This is an **output-size guard, not a process memory limit**: preview overlap, decoder scratch space and graphics copies can add memory. Full images are not tiled or cached across tabs. Viewer decodes are serialised even when an old native decode has been cancelled; thumbnails retain their separate two-operation gate. Cancellation disposes any late result without attaching it to the wrong or hidden tab.

No changes to Windows, the shared core, dependency versions, session schema, NVIDIA/CUDA packages or Python environment are required. EXIF orientation/colour-management parity, advanced codecs, GPU decode, three-image preloading and disk caching remain separate work.

## Automated checks

`bash linux/check.sh` retains the original core/session and browser-policy suites and adds independent viewport/decode-policy tests. `bash linux/smoke.sh` retains browser and fresh-process folder/tab/active-tab restoration checks and exercises a generated 6000x2000 source with one-pixel stripes, actual-size decode, root-coordinate wheel input, pointer capture/drag/release, Fit, tab-state retention, hidden-tab disposal, cancellation and corrupt-image error handling. All data/state is disposable. No user images are uploaded. A generated screenshot is not a human visual review.

## Native Nova acceptance

Close the old application normally. In the clean linux/ubuntu-gnome checkout, update with `git pull --ff-only origin linux/ubuntu-gnome`, run `bash linux/check.sh`, and launch `bash linux/run.sh`. Expect L002b in the title. No new apt packages are required for the normal update.

Open a PNG/JPEG image tab. Try wheel zoom on a recognisable detail, left-drag it, select 100% and Fit, then switch to another image and back. Check that the first tab's viewing position returns. Repeat with an image wider than 4096 pixels and wait for full resolution before evaluating detail. Recheck the browser and ordinary close/relaunch session restoration; view transforms should reset to Fit after a full restart. Test fractional scaling and fullscreen separately on the actual desktop.

Reference APIs checked: Avalonia custom rendering, pointer devices, TopLevel.RenderScaling/ScalingChanged, and PointerEventArgs root-to-control coordinates. These sources describe APIs, not verification of Myoken on Nova.
