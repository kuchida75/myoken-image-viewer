## Current iteration

L003d adds **first-frame JPEG XL** through PhotoSauce.NativeCodecs.Libjxl 0.12.0-preview1. Keep the package in Myoken.Linux; runtime native libjxl comes from NuGet, while Ubuntu `libjxl-tools/cjxl` is CI fixture-generation only. AdvancedCodecRegistry must register libheif and libjxl together because CodecManager is process-global. JxlDecoder must use the public `JxlDecoderOptions(0..1)`, normalize orientation/profile to sRGB, preserve alpha through BGRA32, and keep existing pixel guards/caches. Do not claim animation, >8-bit/HDR precision, cheap thumbnail native decoding or detailed JXL EXIF/XMP extraction. Retain the real lossless-alpha fixture, exact alpha assertion, PreviewCache assertion and HEIC-after-JXL registry assertion. See linux/L003D-JPEG-XL.md.

L003c adds **HEIC/HEIF/AVIF primary-image decoding** through PhotoSauce.NativeCodecs.Libheif 1.23.5-preview1. Keep this dependency in Myoken.Linux, not Myoken.Core. Runtime native decoders come from the NuGet package; do not add a host libheif APT requirement for users. The CI-only Ubuntu heif encoder packages exist solely to generate real disposable fixtures. Route decoded output through MagicScaler `OrientationMode.Normalize` + `ColorProfileMode.ConvertToSrgb`, then into existing BGRA/Avalonia caches. Preserve the 120M input/64M full-output guards. Do not claim animation/auxiliary images, alpha preservation, >8-bit/HDR fidelity or cheap thumbnail decoding: the current PhotoSauce libheif source is 8-bit RGB and performs primary native decode before resize. Retain actual HEIC **and** AVIF integration tests plus Info/metadata and cache assertions. JPEG XL is separate. See linux/L003C-HEIC-AVIF.md.

L003b normalises Skia-recognised tagged non-sRGB sources into **sRGB working pixels before caching**. Keep the TopLeft sRGB/untagged Avalonia fast path; route non-sRGB tagged sources through a Skia decode targeting sRGB. Oriented sources already on the Skia path must also preserve sRGB through resize/orientation intermediates. Info/status may report source space and conversion state. **Do not claim monitor-profile colour management or HDR:** no Myoken display-profile transform exists yet. Untagged sources are treated as sRGB. Retain the tagged Display P3 numeric reference test and all L003a orientation checks. See linux/L003B-COLOR-MANAGEMENT.md.

L003a applies encoded/EXIF orientation before thumbnail or preview caching. Values 1-8, including mirrored/transposed cases, are normalized into visually oriented bitmap pixels; ImageViewport uses oriented display dimensions while metadata can still expose encoded dimensions. Keep TopLeft images on the established Avalonia decode path and keep pixel transforms in Myoken.Linux. Portable ImageOrientation, metadata DTOs and MetadataExtractor-based parsing live in Myoken.Core without Avalonia/Skia/WPF/Win32 dependencies. The Info panel is lazy/read-only and Refresh must invalidate and reread visible metadata safely. **Do not claim colour management:** the colour-space field is descriptive metadata only and no ICC/profile transform exists yet. See linux/L003A-ORIENTATION-METADATA.md.

L002c4 adds low-priority warming of neighbouring **open image tabs** after the foreground selection has loaded: next, previous, then second-next, with no wrap. PreviewPreloader owns only cancellation/scheduling; it immediately releases every warmed lease so PreviewCache remains the sole bounded owner. Selection changes, Browser, Refresh and shutdown cancel old schedules. ViewerImageLoader uses PriorityAsyncGate: pending foreground work must be dequeued before pending background preload work, although a native decode already running cannot be forcibly pre-empted. Never preload full-resolution upgrades. See linux/L002C-PRELOAD.md.

L002c3 adds a shared **512 MiB** viewer-preview RAM cache with a 256-entry cap. ImageViewer holds a preview lease while active and releases it on suspension; the cache may retain that preview for reuse. Explicit full-resolution upgrades remain uncached and must never be inserted into PreviewCache. Cache keys use exact path plus file length/UTC mtime; Refresh clears preview and thumbnail caches. Preview-cache eviction/clear/shutdown must preserve outstanding leases and reject late decode results. The retained-byte budget is not total process/GPU memory. Zoom/pan and sampling state stay on the tab model and survive preview release/reacquisition but are still not persisted across restart. See linux/L002C-PREVIEW-CACHE.md.

L002c2 adds a browser-owned 128 MiB thumbnail RAM cache with an 8192-entry cap. LeasedLruCache owns retained entries; visible Tile objects own leases, never raw bitmap disposal. Eviction/clear removes cache ownership but must preserve displayed leases. Dispose late/cancelled decoded results. Metadata keys include ordinal full path, requested edge, length and UTC mtime; same-size/same-mtime changes require Refresh/F5. Metadata checks do not constitute filesystem watching or content hashing. Clearing/shutdown changes a generation, preventing old acquisitions from repopulating the cache. Two acquisition slots bound work; duplicate misses can decode twice but only one result is retained. Do not claim the retained-byte estimate is total process/GPU memory. The footer reports estimates and lifetime counters. See linux/L002C-CACHE.md for completed tests and remaining Nova acceptance.

L002c1: DocumentTab is transient identity/content, not a persisted DTO. DocumentTabs owns the single-row header controls, pinned Browser, horizontal scrolling, open-tabs popup and selection. MainWindow owns viewers, decoding activation, closing and unchanged session writes. Never reset the selected content or fire selection change when closing only an inactive tab. Header keyboard navigation is distinct from viewer pan keys. Browser is not closable; active-close fallback is right neighbour, then left, then Browser. The user reported this workflow "all good" on Nova; see linux/L002C-TABS.md.

L002b: ImageViewer owns active-tab decoding and transient per-tab geometry/sampling mode. ImageSurface draws/handles pointer input; ImageViewport holds pure geometry; ViewerDecodePolicy/ViewerImageLoader enforce output-size guards. Inactive image tabs retain geometry, not decoded viewer bitmaps. Viewer preview/full-resolution images are NOT in the new thumbnail cache. Source pixels, preview pixels, DIP units and render-target pixels differ. Zoom/pan and Smooth/Pixels choice are not persisted across restart. Routed pointer tests use presentation-root coordinates.

L002a folder tree is lazy, not virtualised; filenames are fully scanned/sorted. The thumbnail controls are virtualised and own visible leases; cached off-screen thumbnail bitmaps can now remain resident within budget. Do not infer 100k-folder throughput from repeated fixture paths. Thumbnail and serial viewer decode gates remain separate. Preview caching and neighbour preloading are implemented through L002c4. L003a adds orientation/basic metadata, L003b source-profile normalization, L003c HEIC/HEIF/AVIF and L003d first-frame JPEG XL. Monitor-profile/HDR output, richer multi-frame/metadata codec support and disk caching remain future work.
