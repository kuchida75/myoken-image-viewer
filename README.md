# Myoken Image Viewer

Myoken Image Viewer (formerly Zen Image Viewer) is a Windows-native C#/WPF photo browser and image viewer, with tabs, a three-pane workspace and GPU-accelerated rendering. It uses an original simplified teal/ivory shutter icon; no proprietary photo-app branding or assets are used.

Repository: [kuchida75/myoken-image-viewer](https://github.com/kuchida75/myoken-image-viewer). The first Myoken build is **0.2.167**; the original Windows source baseline remains tagged **v0.2.166**. A fresh Git clone contains source, tests, assets, notices and dependency manifests, but **not** compiled runtimes, AI weights or an executable. Follow [Build from source](docs/BUILDING.md) before using the build commands below. References to bundled/offline builds elsewhere describe a full local package or a working tree whose dependencies have already been restored.

## Tab Stacks

Right-click any image or folder tab and choose **Tab stack > New stack...**. Enter a name and check the tabs to combine. **Move to stack** moves an individual tab to an existing stack; **Manage tabs** edits the name and checked membership together. The fixed Browser command can be duplicated into an ordinary folder tab first.

Click a stack header or its arrow to collapse/expand the group. The header's options menu lists every member, including the active tab, and offers **Rename stack**, **Manage tabs**, and **Unstack all tabs**. Unstacking never closes tabs or changes their images, folder views, adjustments or pins. **Remove tab from stack** detaches one tab. Duplicates inherit the source stack but not its pin. Empty stacks disappear; a stack with one remaining member retains its name.

Drag a stack header to reorder the entire block. Drag individual tabs before another member to join/reorder within its stack; drop before a stack header, before an ungrouped tab or at the row's end to detach. Stack members stay contiguous. Ordinary tabs retain their existing reorder behavior, active-width sizing and thumbnail previews; grouped tabs share a color, while pinned tabs retain the configured pinned color. Collapsing does not switch or close the displayed image. The active stack stays highlighted, and its menu can switch hidden members.

Automatic restore, named sessions, JSON export/import and reset recovery backups preserve stack IDs/names, membership, order and collapsed state. Old sessions/backups need no migration. Backup import removes missing image tabs and any newly empty stacks, including within named sessions; malformed stack references are rejected before import. Stacks are window-local and single-level, not nested or shared between app windows.

After building with tests, run `artifacts\tests\ViewerRegressionTests.exe --tab-stacks-only` for stack controls, dark/light previews, drag integration, pin/duplicate/unstack behavior, auto/named restore, backups/missing-file cleanup, reset and older-profile compatibility, followed by existing tab-width/reorder/backup checks. Tests use generated images and isolated profiles only.

## Batch Tools

Select items in the thumbnail browser, then choose **Batch** on the browser toolbar, **File > Batch**, or a thumbnail's right-click menu. The same commands work on the displayed image. Settings appear on the left and a virtualized **current name / new name / dimensions / status** preview on the right. Changes rebuild the preview in the background. Uncheck **Use** to exclude individual rows; included errors prevent execution. The final Rename/Resize/Convert button asks for confirmation. **Cancel / Esc** requests a safe stop and keeps the result report open.

- **Rename:** files and folders, with extensions protected. `*` / `{name}` insert the original stem; runs of `#` insert a padded sequence with explicit Start and Step. Letter sequences use A-Z, AA, AB, etc. Metadata tokens include `{folder}`, `{created:yyyyMMdd}`, `{modified:yyyyMMdd}`, `{taken:yyyyMMdd}`, `{width}` and `{height}`. Missing image metadata is reported, not guessed. Text rules run in this order: template, find/replace, remove text, remove first/last characters, prefix/suffix, strip whitespace, case change. Folder names use the complete original name. Sequence order follows the selected browser order, not the order in which files finish processing.
- **Resize:** bounding-box pixels, percentage, print size in inches/cm with DPI, long edge or short edge. Choose aspect-ratio preservation, width/height/both fitting, and enlarge/reduce restrictions. Defaults are reduce-only, original format and a `_resized` suffix. Another output format can be selected, including when the source is HEIC/HEIF.
- **Convert:** JPEG, PNG, WebP, AVIF, JPEG XL or still GIF. Set quality, lossless WebP/JPEG XL, metadata and last-modified-date preservation. Use each source folder (blank Folder), an explicit destination, an optional single subfolder and/or a filename suffix. HEIC/HEIF decoding is bundled, but HEIC encoding is not; unsupported output formats are reported instead of silently substituted.
- **Conflicts:** Keep both generates a unique name in the preview; Skip omits the item; Stop for review reports an error. Resize/conversion also offer **Overwrite + backup**, with explicit confirmation and an original backup under `.zen-batch-backups` beside each overwritten destination. Rename never overwrites an unrelated item. Late conflicts or changed source/destination revisions are refused.
- **Presets:** save/delete up to 32 named presets across the three tools. They belong to the current window's workspace and are included in automatic/named sessions, backup export/import and Reset. Default remains available separately.

Batch export reads **on-disk originals**, not transient Quick Enhance, manual sliders, view rotations or AI-upscale previews. It uses the bundled CPU codecs with up to four concurrent image jobs, cancellation between native codec stages, verified temporary output and a 128-megapixel limit. It is not a GPU batch-encoding pipeline. Output is **8-bit**; JPEG transparency is flattened onto white and GIF is palette-limited. Orientation is normalized and EXIF dimensions/thumbnails updated. Metadata preservation is format-dependent, not a guarantee for every vendor field or XMP dimension field. Removing metadata retains color interpretation (ICC or standard sRGB data). Animated/multi-image files and folders are skipped by export; folders are not recursively converted. Originals are never automatically deleted.

Rename stages items under unique temporary names so cycles and case-only changes work. Failure/cancellation attempts rollback. A source/temp/destination JSON recovery map is kept in the profile's `batch-logs` directory before any move and updated afterward. Multi-file rename is **not a filesystem transaction**: a crash or external interference can require manual recovery using that log. There is no one-click undo or automatic crash recovery yet. File links/junction ancestors and renaming the active profile or its parents are refused. Open tabs, folder favorites and navigation paths are remapped simultaneously; preserved-date overwrites invalidate thumbnail caches and displayed GPU/CPU pixels.

Run `artifacts\tests\ViewerRegressionTests.exe --batch-only` after building with tests. Tests use isolated profiles/generated images, exercise all six encoders, conflicts/rollback/backups, metadata, rename/tab compatibility, same-date/size cache invalidation, presets and native dark/light/minimum-size dialogs. The 100k-row check verifies UI virtualization, not end-to-end throughput on 100k real photos. The destination folder chooser and confirmation prompts remain manual smoke checks.

## GPU Image Pipeline And Eviction

**Configure > Performance** includes **GPU-resident image rendering**, **Image GPU**, **Image VRAM limit**, and **NVIDIA GPU-assisted JPEG decoding**. Defaults are enabled, automatic discrete-adapter preference, and a **4096 MB** resident-texture allowance. These preferences persist in automatic/named sessions and backups. The existing decoded cache limit controls CPU-side bitmaps separately.

Images are held in an explicitly owned **Direct3D 11 texture cache**, shared with WPF through D3D9Ex/D3DImage. Scaling, panning, rotation and existing enhancement shaders compose the GPU image with normal WPF overlays. Previous/current/next preloading warms these textures; unchanged cached images reuse them instead of uploading again. File revisions and decoded color-policy identity prevent stale reuse; transient AI pixels are treated separately. This is a real GPU-resident path, not a D3D12 rewrite.

Supported JPEGs use bundled **nvJPEG hybrid CPU/GPU decoding**, writing directly into a CUDA-registered D3D11 buffer, followed by a GPU conversion to the display texture. No CUDA toolkit installation is needed. A CPU bitmap mirror is read back once for the existing analysis, editing, navigator, print and export workflows; this build is not a GPU-only end-to-end editing pipeline. GPU JPEG decoding is bypassed for ICC-enabled images and unsupported layouts/devices/drivers. Other formats use their existing CPU decoder followed by one texture upload. Animated GIFs, oversized shared textures and unavailable devices retain the WPF path. Originals are unchanged.

The cache samples **IDXGIAdapter3's live process usage and Windows memory budget** before allocations and once per second. Its effective allowance is the smaller of the user limit and remaining Windows budget, allowing for other GPU allocations and up to 256 MB headroom. Least-recently-used inactive textures are released first. A displayed surface stays alive until the UI switches to its CPU mirror; only then can it be released. Unknown/exhausted budgets reject new allocations, and GPU/device failures fall back with retry. Limits apply per window; CUDA, driver, WPF and AI working memory are additional, so this is not a hard cap on total process or system VRAM.

The status row shows resident **Image VRAM** and whether the current image uses **GPU** or **WPF** presentation. Configure provides the selected adapter, effective allowance, Windows process budget/usage, cached texture count, hits, uploads, GPU JPEG decodes, evictions and fallback reasons. System-wide iGPU/dGPU counters remain separate.

Run `artifacts\tests\ViewerRegressionTests.exe --gpu-image-pipeline-only` after building tests. Checks exercise actual RTX texture sharing and nvJPEG output, pixel parity, controlled budget-pressure eviction, pinned-surface lifetime, invalidation, renderer fallback, enhancements, navigator, print preview and settings/backups using generated fixtures. Budget drops are simulated against real textures, not created by exhausting this PC's VRAM. GPU hot-unplug/TDR and cross-monitor adapter migration require manual validation. No broad codec-throughput or real 100k-file benchmark is claimed.

Version 0.2.145 passed this suite on the RTX 5090. `--gpu-compatibility-only` also passed saved-image keyboard navigation, overwrite preferences, full-resolution enhancement export, all supported formats/GIF playback, Configure, zoom controls and actual DirectML AI upscaling. Image navigation now retains input during post-save/file-watcher refreshes and cancels deferred input when leaving the view. The existing dual-GPU checks also passed on the RTX 5090 and AMD integrated GPU during this change.

The runtime and NVIDIA license/provenance files are bundled under `GpuRuntime`; `tools/prepare-gpu-runtime.ps1` reproduces checksum-verified downloads into the project. See [nvJPEG](https://docs.nvidia.com/cuda/nvjpeg/) and [WPF Direct3D interoperability](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/advanced/wpf-and-direct3d9-interoperation).

## Dual-GPU Processing

**Configure > Performance** now provides:

- **AI enhancement GPU:** Automatic (prefers a discrete adapter), CPU, or a specific installed GPU. Advanced Quick Enhance's DirectML subject models use that exact adapter index, resolved from a saved hardware identity rather than assuming GPU 0 is the RTX. A missing selected adapter falls back to CPU without discarding the preference.
- **Thumbnail processing:** Auto, CPU, or Integrated GPU. The integrated path creates a separate low-priority Direct3D 11 compute device and area-resizes thumbnails with alpha-aware filtering. CPU workers still handle indexing, EXIF, image decoding, an intermediate image bounded to twice the target size, and disk-cache encoding. GPU output returns to CPU memory for the persistent JPEG cache. Existing cache hits do not invoke either resize path; Rebuild thumbnails refreshes them.
- **Auto comparison:** Three uncached samples per format/small-or-large size class compare CPU decode/resize against the complete GPU path, including intermediate decode, upload, dispatch, readback and budget checks. GPU initialization is excluded from timing. Auto uses the iGPU only when the measured path is at least 20% faster; otherwise it keeps CPU processing. Recheck performance restarts this per-window comparison. It is a conservative local sample, not a universal throughput benchmark.
- **AI GPU soft limit:** Defaults to 2048 MB. DXGI checks current process usage against this admission limit and Windows' local-memory budget before a new model, allowing 256 MB estimated headroom. Pressure on reused models releases GPU sessions and falls back to CPU. This is not a hard allocator cap: WPF/ONNX/driver allocations can exceed estimates, and no promise is made that total VRAM stays under this number.
- **Thumbnail GPU limit:** Defaults to 128 MB for the estimated input/output/readback texture working set. Jobs exceeding this cap or DXGI headroom use CPU. Driver/device overhead is separate. One GPU thumbnail runs at a time; other CPU workers continue normally instead of waiting. Device errors fall back to CPU, with retry after 30 seconds. CPU mode, reset and closing release the background device asynchronously.

The expanded Performance bar shows **RTX/dGPU and iGPU memory separately**, including dedicated usage/capacity and shared-system-RAM usage. Configure includes full adapter names and shared capacity. These readings are **system-wide**, across all applications, not this viewer's allocations. The iGPU is identified by its unified-memory architecture, not by a guessed memory-size threshold. Missing counters display unavailable, not zero. Shared RAM is not added to the dedicated VRAM total.

Each adapter is numbered **GPU 0, GPU 1, ...** using the same DXGI index as the viewer's GPU selector. Dedicated usage is bold cyan, shared-RAM usage bold amber, and capacity/labels muted. Colors adapt immediately to dark/light themes; unknown readings remain muted. Fixed-width adapter slots and tabular digits make changing values easier to scan without shifting the neighboring GPU. Hover for the full adapter name and memory definitions. Numbers are the viewer's adapter indices, not a promise of matching another monitoring application's ordering.

GPU preferences and limits persist in automatic/named sessions and JSON backups; Reset restores Auto/2048 MB/128 MB for AI/thumbnail processing and Auto/4096 MB for resident image textures. Actual processing/fallback status and GPU resize counts appear in Configure. There is no combined VRAM pool. The image-GPU selector controls the shared-texture cache; WPF still chooses its composition/display adapter through Windows, independently of the AI selector. Indexing remains CPU/filesystem work. A second GPU is optional; CPU fallback keeps browsing functional.

Run `artifacts\tests\ViewerRegressionTests.exe --gpu-only` for real hardware shader pixel/readback/alpha checks on both adapters, concurrent RTX DirectML and iGPU resize work, memory admission and working-set limits, CPU/Auto behavior, cache hits, separate telemetry, narrow layout and saved configuration. Tests use generated images and isolated profiles.

## Reset And Thumbnail Cache

**Configure > Reset viewer...** restores defaults and clears open tabs (including pinned tabs), all saved sessions, favorites/aliases, expanded tree state, recent searches and custom shortcuts. It returns the viewer to normal mode and default window placement. Original photos are never changed. Close other viewer windows using the same profile first; maintenance is blocked while another instance is open.

Thumbnail cache is **kept by default**. Tick **Also clear thumbnail cache** to discard all cached thumbnail sizes, or use **Configure > Performance > Clear cache...** independently without resetting settings. Thumbnails regenerate as you browse; previews already in use may regenerate immediately. Wait for or cancel an explicit thumbnail rebuild before maintenance. Decoded image memory is released on reset; downloaded models, photo-save backups and prior recovery backups are retained.

Before resetting, a restorable JSON backup is saved under the profile's `backups/before-reset-<timestamp>/viewer-backup.json`, with raw copies of old settings (including other windows' saved sessions and unreadable session files) under `original-settings`. Use Sessions > Import backup to restore the active workspace and named sessions. Backups are deliberately retained, so Reset is not a secure-erasure operation.

## Manual Enhance

### Zoom Controls

The top toolbar includes **Zoom lock**, **Fit width**, **Fit height**, and **original size (1:1)** icons. Hover for a description and any assigned shortcut. Width and height fitting preserve proportions and center the image; drag to pan any overflowing dimension. These explicit fit actions may enlarge small images. The existing **Fit image / 0** command still avoids enlarging them. The 1:1 button shows the currently displayed pixels at 100%, including applied AI pixels.

**Zoom lock** highlights when on and keeps the same zoom across images, tabs, rotation and window resizing. Zoom gestures and sizing buttons can still change the locked level. AI-resolution changes keep the same apparent image size while locked. Unlocking keeps the current view; newly opened images resume normal fitting. The setting and level are saved in automatic/named sessions and exported backups; reset and older profiles default to unlocked. Configure > Shortcuts can assign keys to all four commands; new commands have no default bindings.

### Printing

Open an image and use the printer icon or **Ctrl+P** for **Print preview**. This image-only shortcut can be rebound under Configure > Shortcuts; existing custom Ctrl+P assignments take precedence. Printing is unavailable while the image, enhancement or AI upscale is still processing.

The preview captures the full current image with visible Quick Enhance, manual sliders, rotation and any applied AI upscale. It does not print the viewport crop, controls, metadata overlays, filmstrip or background theme. Animated images print the captured frame. Slideshow stops when preview opens. The source file is never changed.

Choose an installed Windows printer, one of its reported paper sizes, portrait/landscape, **Fit entire image** or **Fill (crop edges)**, margins in millimeters and 1-99 copies (subject to driver support). Fit centers the full image without changing its aspect ratio. Fill centers and crops to the available area. Margins are measured from physical paper edges and also respect the driver's non-printable area. Preview zoom does not affect output size. White paper shows through transparent image pixels. Effective DPI is shown for the selected print size.

Print settings are checked against the selected driver before enabling **Print**. Rendering and printer capability reads run in the background; submission is asynchronous. Opening or closing preview never submits a print job. **Print** sends the same page layout to the Windows queue; a PDF/XPS printer may then ask for a destination filename. A successful submission does not confirm physical printing. Cancellation cannot recall pages already accepted by the printer; use the Windows queue if needed. If no usable printer is available, the window still offers a preview but printing is disabled.

Initial scope: one current image per page; no batch/contact-sheet printing, printer-specific property editor or print soft-proofing. Driver defaults control color/quality beyond the exposed page settings, and explicit ICC color management remains unimplemented. No Windows printer defaults are changed. Tests cover the actual one-page XPS serialization path and installed PDF-driver settings without sending physical print jobs: `artifacts\tests\ViewerRegressionTests.exe --print-only`.

### AI Super-Resolution

The arrow attached to **AI upscale** selects **Basic**, **Real-ESRGAN**, **HAT / Real-HAT**, **SwinIR-M Real-World x4**, or **SUPIR**. The main button and **S** use that model. Selection is also in Configure > Image tools, persists in sessions/backups, and defaults to Basic for older profiles. Switching an active preview cancels obsolete work and rebuilds from original pixels. Status identifies the model used; missing/failed models never silently fall back to Basic.

Upscale feedback is color-coded in dark and light themes: **amber** while processing or after cancellation, **green** when applied, **blue** for original-resolution bypass, and **red** for errors. Text continues to describe the state. The split button and footer scale also change color while processing/active; hover does not hide the highlight. Canceling a scale change keeps the previous preview's active button color. Switching off or navigating away restores the neutral button. The manual preview dialog uses matching status/progress colors. Run `artifacts\tests\ViewerRegressionTests.exe --upscale-status-only` for focused color/state/contrast checks.

**Basic** is the original small 3x luminance CNN. **Real-ESRGAN** uses the bundled RealESRGAN_x4plus checkpoint; **HAT / Real-HAT** uses the bundled Real_HAT_GAN_SRx4 fidelity-oriented variant, not the sharper variant or classical HAT checkpoint. **SwinIR-M Real-World x4** uses the official `003_realSR_BSRGAN_DFO_s64w8_SwinIR-M_x4_GAN.pth` EMA weights, not SwinIR-L, lightweight or classical SR. These three RGB models run offline through DirectML/CPU with fixed 128px input tiles, 32px halos, native 4x reconstruction and filtering to the selected 1x-3x factor. No Python installation is needed to run them. All four bundled models retain the existing bounded luminance-detail blending, original chroma/alpha, subject weighting and approximate skin-color safeguards; their output deliberately differs from unmodified upstream RGB inference. Stronger models can still invent or smooth texture. Memory admission estimates are 192 MB (Basic), 768 MB (Real-ESRGAN) and 1536 MB (Real-HAT and SwinIR-M), not hard VRAM guarantees.

**SUPIR is optional and experimental.** Choose **AI upscale > SUPIR setup...** to connect a separately installed, trusted Python/CUDA environment and the official SUPIR repository. Install its dependencies, SDXL base, SUPIR-v0F, and locally cached text encoders, then configure `options/SUPIR_v0.yaml` and `CKPT_PTH.py` following the [upstream setup](https://github.com/Fanghua-Yu/SUPIR). The viewer does not install or download these multi-gigabyte components. It runs the bundled `Tools/viewer-supir.py` adapter with offline flags, no LLaVA, 20 diffusion steps, fidelity-oriented settings and a fixed seed. It requires the selected NVIDIA GPU to match a unique CUDA device, at least 12288 MB AI allowance, and output no larger than 4.2 MP after 64px padding. CUDA allocator limits supplement DXGI admission; these remain soft overall memory limits. A failed/unsupported environment reports its error without substituting another model. Local runtime paths live in the machine profile, are not included in backups, and are not transferred between PCs. Connecting authorizes executing that trusted local Python/repository. **Full SUPIR inference is not verified in this release**; setup checks paths only, and successful inference also requires compatible checkpoints, dependencies and drivers. Review SUPIR/SDXL license terms separately; no checkpoints are redistributed here.

Press **S** in image mode or click the labeled **AI upscale** button on the top row for automatic, view-only upscaling. It compares native image pixels with the current frame's physical pixels, including Windows display scaling and rotation, and chooses the next supported scale up to 3x. If the image already fills the frame at native resolution (within 10%), it is left unchanged. Processing also respects the 8 MP source / 32 MP output limits. Press again to cancel processing or restore the original. No file is changed; Enhance adjustments remain live. Navigation/reload closes the transient preview, and it is not restored on restart. Use Enhance > Save As to keep a copy. S is rebindable; an existing custom S assignment is preserved.

While inline AI upscale is active, the bottom status bar shows an **AI upscale** slider and its selected factor: **1x, 1.25x, 1.4x, 1.6x, 1.8x, 2x, 2.5x or 3x**. The maximum is reduced when necessary to stay within the 32 MP output limit. Changes rebuild from original pixels after a 300 ms pause; rapid changes cancel obsolete work and keep the previous preview visible until the new one is ready. At **1x**, original pixels are shown without AI, and the slider remains available. Focused arrow/Home/End keys adjust the slider rather than navigating images. S cancels a pending change, or switches upscale off when idle. No file is changed; Enhance > Save As exports the applied scale. The slider hides on exit/navigation and its transient factor is not saved in sessions.

For manual scale selection and comparison, choose **Configure > Image tools > Super-resolution**. The dialog captures the original image, Quick Enhance, all ten sliders and rotation. Choose **1x, 1.25x, 1.4x, 1.6x, 1.8x, 2x, 2.5x or 3x**, then **Preview**. 1x bypasses AI for an original-resolution comparison. **Original** compares the same adjustments without AI detail at the same display size; **1:1** displays actual output pixels with scrolling. The manually chosen factor is remembered; unsaved previews are not session files.

AI processing is local and cancellable. The Basic [ONNX sub-pixel CNN](https://github.com/onnx/models/tree/main/validated/vision/super_resolution/sub_pixel_cnn_2016) predicts 3x luminance detail; Real-ESRGAN, Real-HAT and [SwinIR-M](https://github.com/JingyunLiang/SwinIR) reconstruct at 4x. Intermediate factors use area filtering, never repeated upscaling of previous results. Person/general-subject masks vary reconstruction strength separately from the background. Warm skin-like colors receive gentler detail, and a common RGB luminance offset preserves source chroma without whitening or assigning a target complexion. These are approximate protections, not calibrated skin segmentation or a guarantee of natural-looking results. Current Quick Enhance and all manual values apply after reconstruction, so deliberate color changes remain under user control.

**Save As** exports a separate image and opens it in a new tab. The original cannot be overwritten through this workflow. Replacing another existing destination requires confirmation and uses the existing backup/changed-file protection. Output is 8-bit sRGB with PNG/WebP/JPEG XL lossless options or JPEG/AVIF; transparency follows existing encoder behavior. Animation exports the captured frame only. Already-baked adjustments are not applied again when the saved result opens.

The bundled ONNX models use **Configure > Performance > AI enhancement GPU** (Auto prefers the discrete GPU), the AI soft memory limit and between-tile DXGI pressure checks, with same-model CPU fallback. ### Advanced Quick Enhance

At most forty 128x128 native-resolution patches are analyzed with up to eight workers, including extra mask-guided locations for small/off-center subjects. This uses the existing Advanced setting across tabs and sessions; there is no extra switch.

The same WPF shader applies regional sharpening through the existing mask/lookup textures, with skin-color protection, noise rejection and a bounded luminance correction to limit halos. Preview processing does not modify files or thumbnails/EXIF; explicitly saving from Enhance writes the visible result. Focus analysis is a heuristic based on edge concentration and noise, not a deblurring model: severe defocus/motion blur and absent detail cannot be reconstructed, and textureless subjects may receive no sharpening. Sampling retains native pixel scale instead of judging focus only from a downscaled overview.

Technical references: [OpenCV's Laplace operator notes](https://docs.opencv.org/4.13.0/d5/db5/tutorial_laplace_operator.html) describe noise sensitivity in derivative-based edge analysis; [Microsoft's pixel shader limits](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/dx9-graphics-reference-asm-ps-differences) document the WPF PS 2.0 budget. The viewer uses its existing C#/WPF pipeline, not a new OpenCV dependency.

Choose **Advanced** under **Configure > Images > Enhance mode**. Selecting a mode enables enhancement; the existing Quick Enhance button switches that mode on/off. **Basic** retains the earlier exposure/sharpness analysis. **Advanced** incorporates that analysis and adds independently measured subject/background exposure, shadow lifting, highlight compression and restrained vibrance. The mode and on/off state apply across all tabs in this window and survive automatic/named sessions and JSON backup/restore. Browser thumbnails remain unchanged.

Advanced first looks for people using PPHumanSeg, then tries U-2-NetP for other prominent subjects. Both models run locally with DirectML on the GPU selected in Configure > Performance (Auto prefers discrete), and retry on CPU if GPU initialization/inference or memory admission fails. No photos are uploaded. The first use initializes the models and may take longer; subsequent images reuse the sessions. Switching tabs/modes or AI GPU settings cancels pending work and stale results cannot replace the current image. Turning enhancement off restores the original decoded view, with no image/EXIF changes, and releases the model sessions asynchronously.

Separate tone curves are blended through a softly feathered, edge-aware subject mask. Hue-preserving luminance changes, gamut compression, reduced sharpening and suppressed vibrance in likely skin-colored areas help avoid unnatural portraits. Skin protection is a conservative hue/chroma heuristic across brightness levels, not calibrated skin recognition; it may also protect warm-colored objects. It does not identify people, infer ethnicity, smooth skin or reconstruct missing detail. There is no universal guarantee of natural color under every light source. Basic/Off remain available for comparison.

Subject masks are approximate, especially around fine hair, transparent material, small people and unusual scenes. If there is no confident subject, or a model is missing/corrupt, Advanced applies gentler global adjustments and reports this in the Quick Enhance tooltip. Highlight compression preserves existing detail but cannot recover clipped whites; shadow lifting cannot recreate lost information. Analysis uses a 512-pixel-long-edge control map and a 256-level interpolated tone table, plus Basic's 768-pixel analysis. Rendering remains WPF PS 2.0 with software fallback, while model inference is separate. Its memory is separate from the decoded cache; the new AI GPU soft limit controls admission, not a unified hard VRAM budget.

## Stubbed or intentionally conservative in this prototype

- File transfers are serialized, with per-item progress and conflict confirmation. Linked files, symlinks and junction folders are rejected, as are drive roots and copying a folder into itself. Transfers cannot be interrupted mid-file from the UI, and the app waits for a transfer before closing. Failures may leave partial output; there is no transactional rollback. Single-item Rename/Move/Delete buttons still operate on image files; grouped file/folder moves use Cut/Paste. Multi-delete and multi-rename are not implemented.
- Quick Enhance is a heuristic, not a guarantee of the best appearance for every photograph. It cannot recover clipped exposure or missing detail from severe blur. Analysis uses a bounded 768-pixel-long-edge sample and up to eight CPU workers; transparent pixels are excluded. Rendering uses WPF's PS 2.0 shader pipeline (GPU where WPF acceleration is available, software fallback otherwise). Preview reuses the original decoded bitmap without changing files. Enhance Save/Save As explicitly renders the visible effects at full resolution. Shader texture-size limits and rendering performance remain governed by WPF, not an explicit D3D12 image pipeline.
- The image renderer uses real D3D11/D3D9Ex shared-texture residency and nvJPEG hybrid GPU decoding, not D3D12 or nvImageCodec. Non-JPEG codecs still decode on CPU, a CPU mirror remains for editing/export, and animated GIFs use WPF presentation. WPF controls composition and may use software fallback.
- Advanced's local ONNX subject inference can run on DirectML, but this does not change the WPF image decoder/cache architecture. Bundled model/runtime working memory is separate from the decoded-image cache budget. See the Advanced section and included dependency notices.
- Resident GPU textures now have real DXGI-budget-aware LRU eviction. User limits are texture allowances, not strict caps on CUDA, WPF, model or driver allocations. GPU reset and cross-monitor migration still need physical smoke tests.
- Modern decoders use 8-bit display output; HDR and RAW are not supported. Non-GIF animations and multi-image containers show only the first/primary image.
- ICC is exposed as an optional toggle; full low-priority background color-management scheduling is not implemented.
- RAW formats, ratings/tags, duplicate detection, and NAS-specific features are intentionally omitted.

They cover fit/rendered pixels, DPI, pan, tab switching, resizing, metadata visibility, hover previews, themes, fullscreen, window placement, wheel navigation/zoom, same-tab image/browser transitions, mixed session restore, independent browser scroll/search/selection, thumbnail sliders/cache, narrow layouts, 100k-record virtualization, and canceled scans. Folder checks cover sorting, four/two/zero-preview mosaics, corrupt-image fallback, live image and directory changes, folder navigation/search, folder-only session tabs, and releasing hidden folder watchers. They do not use your normal profile or images. Virtualization is tested with 100k in-memory records, not a 100k-file disk benchmark.

`artifacts\tests\ViewerRegressionTests.exe --favorites-delete-only` checks legacy favorites, alias/description editing and cancellation, reset/unpin behavior, unchanged real paths, retained tree expansion, session isolation and restart, dark/light editor layouts, executable/window version metadata, and real Recycle Bin operations on generated test images only. It covers next/previous/empty-folder deletion, duplicate and unrelated tab retention, descending order, filtered-result fallback, slideshow stopping, cache removal and post-deletion session restore. The full suite includes these checks and leaves its recycled fixtures in the Windows Recycle Bin.

Navigation checks also cover pinning/unpinning, favorite shortcuts, nested tree expansion and collapse across restarts, favorites surviving named-workspace changes, all six sort fields and direction, per-tab sort restoration, wheel navigation in metadata order, dark/light dropdown layouts, and oversized-image dragging with edge clamping, release/capture loss, and saved pan offsets.

Tab/rotation checks cover mouse Back and keyboard parent navigation, independent browser-view copies, overflow access to the + button, visible shadow pixels, left/right rotation pixel orientation, centered rotated views on narrow layouts, rotated pan/zoom limits, automatic/named restore, per-tab rotation isolation, search-field shortcut guards, and unchanged original image bytes.

Forward/exit checks cover nested Forward history, selected-child entry, duplicate/session history isolation, stale paths, capped small-image fit, preserved manual zoom, Esc during dragging/fullscreen/search focus, Enter exits and browser activation, Enter's text-focus guard, and restoring the browser after either exit key. Run `artifacts\tests\ViewerRegressionTests.exe --navigation-only` for these focused checks.

Enhancement checks cover dark/bright exposure correction, soft/sharp/noisy analysis, deterministic parallel results, rendered sharpening and transparency, original-view pixel equality after toggling off, cancellation and stale-result rejection, duplicate image/browser tabs and restart, and embedded Windows icon sizes/transparency. For focused checks, run `artifacts\tests\ViewerRegressionTests.exe --enhancement-only`.

Run `artifacts\tests\ViewerRegressionTests.exe --transfers-only` for multi-selection, 100k-record selected-state virtualization, recursive/empty-folder Copy and Cut, collision rename/skip/cancel, self-copy rejection, clipboard file-list/effect formats, drop acceptance/destination resolution, asynchronous UI transfers, moved-tab paths, all-file counts, selection/session isolation, narrow dark/light layouts, windowed slideshow looping/shuffle/preloading, slow decode timing, corrupt/deleted files, and saved slideshow preferences. Tests never alter the system clipboard or the normal user profile. Image decoding owns and releases its streams even on failure, so damaged images do not keep files locked. Closed windows cannot schedule late session writes. Session replacement retries temporary Windows sharing locks without deleting the previous saved file; a controlled lock regression covers this case.

Actual cross-process Explorer drag gestures and its collision dialog are not automated by this harness. For a manual smoke check, use disposable copies: select several files and a folder, drag to an Explorer destination, then drag them back onto a browser background and a folder tile; verify Copy behavior and original-file preservation. Repeat into an existing destination to check the rename prompt, and test Ctrl+X/Ctrl+V into a different directory. Shell interoperability uses [Windows file-list and preferred-effect clipboard formats](https://learn.microsoft.com/en-us/windows/win32/shell/clipboard).

The build script regenerates the ICO and compiled shader using `tools/BuildAssets.cs` and Windows `d3dcompiler_47.dll`. The distributed source also includes the ready-to-embed shader and icon for project builds.
